## 2026-07-28 — PII-in-UI bug: diagnosis and fix
- **Confirmed by direct DB inspection that two separate PII issues existed, not one.** (1) Transaction descriptions in the ledger contained full Zelle/ACH/wire reference numbers and, in one row, a real street address (an ATM location). This was a **documented, intentional gap** in `pii_filter.py`'s original docstring — not a crash, but exactly what Luther flagged as visible in the UI. (2) Separately, `upload.py` was storing the fully unredacted original PDF text into `statements.raw_text`, even though the copy sent to the AI was correctly redacted. Nothing currently serves `raw_text` back to the frontend, so this wasn't what was visible on screen, but it contradicted the "always-on PII redaction" design intent.
- **Fix scope was Luther's explicit call, not a default assumption**: asked via AskUserQuestion whether to fix only the at-rest bug, or also close the description-embedded-PII gap — he chose both.
- **`pii_filter.py` additions**: labeled reference numbers → `[REF]`; bare 8+ digit unlabeled runs (catches Zelle-style trailing IDs) → `[REF]`; heuristic US street-address matcher → `[ADDRESS]`.
- **Gotcha caught before shipping**: the first version of the address regex had no lookbehind guard, so a date right next to a street address (e.g. a day-of-month like "04" right before the real street number) got matched as the street number instead. Fixed with a negative lookbehind so a number preceded by `/` or `-` can't start an address match.
- **`upload.py` fix**: `raw_text=full_text` → `raw_text=redacted_text` at upload.py:81.
- **Existing test data was cleared from cashflow.db at Luther's request** since it predated the fix; `merchant_map` was left intact. He'll re-upload the same 2 source PDFs next session to verify the fix live in the ledger.

## 2026-07-28 — real bank-statement data had leaked into the public repo itself
- **Luther asked "are we sure there's no PII in our public codebase?" — good instinct, and the answer was no.** A `git grep` sweep found real values from his actual bank statements hardcoded as code comments and test fixtures — some predated tonight (from an earlier session's commit), some was introduced by this session while writing the PII-redaction fix above, ironically. Full account numbers, home address, and full legal name were **not** found anywhere in the repo — the leak was limited to reference numbers, a street address, and one third-party business name. Saved as global feedback memory `feedback_no_real_data_in_repo` so this isn't repeated.
- **Fixed in the working tree first**: `pii_filter.py`, `merchant_mapper.py`, `test_pii_filter.py`, `test_categorization.py`, `test_transactions_api.py`, and this repo's own memory files — all real values replaced with synthetic ones. 53 tests still pass.
- **Then rewrote git history, at Luther's explicit request**, since the real values were also sitting in already-pushed commits on the public `claude/phase-1-extraction` branch. Confirmed via pickaxe search that every affected commit was unique to this branch (none shared with `origin/main`). Used `git filter-repo --replace-text <mapping> --refs claude/phase-1-extraction --force` — the `--refs` flag scopes the rewrite to just that branch and skips filter-repo's default remote-stripping behavior. Created a local backup branch (`backup/phase-1-extraction-pre-scrub-2026-07-28`) before running it.
- **Real mistake made during this operation**: `git filter-repo` resets the working tree to match the rewritten HEAD, which silently discarded several *uncommitted* memory-file edits in progress at the time (this file included). Had to reconstruct them from the harness's own system-reminder diff snapshots. **Lesson: commit or stash everything, including memory files, before running any history-rewriting tool.**
